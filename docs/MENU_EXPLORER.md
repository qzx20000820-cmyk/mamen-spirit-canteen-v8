# 麦门真实菜单探索器（开发者本地）

## 简单复现

Node.js20+，在项目根目录：

```sh
npm ci
npm run explorer:setup
npm run explore:menu
```

探索器会先询问官方工具所需的门店编码，再以隐藏输入读取你自己的Token。门店编码可通过本机MCD_MCP_STORE_CODE环境变量提供，不填入源码或仓库。macOS使用原生隐藏输入框；其他系统要求交互TTY且不回显。也允许进程环境提供MCD_MCP_TOKEN，但不要把真实值写进命令历史、聊天、文件或日志；默认推荐隐藏输入。

去除首尾空白并统一Bearer前缀；内部空格、换行、零宽字符或空Token会在网络请求前被拒绝，不擅自删除内部字符后试错。输入错误需要作者自行决定重新运行；程序不重试。

## 唯一接入实现

沿用官方推荐及早期WorkBuddy连接参数：https://mcp.mcd.cn、Streamable HTTP、Authorization Bearer。协议交给MCP官方TypeScript SDK1.32.1（锁定依赖），不复制WorkBuddy客户端内部代码。旧手写协议客户端和诊断入口已退出公开包，不维护两套入口。

流程：SDK initialize/initialized → tools/list检查query-meals输入结构 → 一次query-meals → 明确业务成功包校验 → 内存分析。工具发现最多5页，只能执行query-meals，禁止任何订单、支付、地址工具。HTTP失败立即停止（SDK可选GET收到405表示服务端不提供通知流，是协议允许的情况，不代表query-meals失败），不自动重连、降级SSE或重新认证。只读调用必须通过SDK及服务端真实结果，不存在演示成功模式。单元测试使用明确标识的OFFLINE fixture，与真实证据完全分离。

## 实际业务价值

成功取得菜单后，按名称保守匹配汉堡、炸鸡、薯条、冰淇淋、苹果、玉米、饮用水、可乐和咖啡等固定类别，报告分类数、去重记录数、类目覆盖与无法识别数量。含套餐/拼盒的名称不推断内部组成，不调用套餐详情，不输出价格或营养建议。

把真实单品类别覆盖与H5独立模拟菜单的食品标签交叉检查，提供薯条+冰淇淋、水果+炸鸡、咖啡+冰淇淋、果蔬+水等**游戏内**组合探索路径。输出的可操作餐品名称只能来自原创模拟菜单。真实菜单缺少某类时标为未确认，不编造可售商品或建议额外购买。

这是独立的开发者查询分析功能；H5仍只使用31个原创餐品和5个模拟套餐，不导入真实结果，也不改变37个成就或玩家存档。

## 隐私、保存与证据

原始响应仅留内存，商品名/编码/价格/图片/任意服务端文字不写盘。仅保存固定标签的聚合分析与脱敏调用阶段记录到本地被忽略的.artifacts/menu-explorer/runs/，权限受限。Token、Cookie、门店参数、完整响应和个人信息不进入日志；不把SDK异常正文直接打印，防止服务端回显凭证。

公开记录仅显式收录MENU_EXPLORER_STATUS.json中的阶段、HTTP状态、工具成功/失败等结果。运行输出不自动进入源码包。聚合结果默认仍私有，不以接口访问成功推定任何菜单再分发权。

## 验证状态

真实最新状态见MENU_EXPLORER_STATUS.json。离线协议/分析/失败测试通过不能算真实调用。真实失败时仍保留可运行模块，标为未验证；不无限排障。即使以后成功，是否满足赛事由主办方依据完整项目判断，不自行宣布资格通过。
